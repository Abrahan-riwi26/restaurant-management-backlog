# HU-013 — Gestión de No-Show

**Épica**
Gestión de Reservas

**Sprint**
Sprint 2

**Prioridad**
Alta

**Story Points**
8

**Dependencias**
HU-007 — Registro de Reserva
HU-011 — Confirmación de Reserva

## Historia de Usuario

**Como** personal autorizado del restaurante

**Quiero** marcar una reserva como no presentada

**Para** liberar la mesa cuando el cliente no llegue dentro del tiempo permitido.

## Objetivo

Permitir que el restaurante gestione las reservas cuyo cliente no se presenta, manteniendo el historial y liberando la disponibilidad de la mesa.

## Descripción Funcional

El personal autorizado podrá marcar una reserva confirmada como `NO_SHOW` cuando el cliente no se presente dentro del tiempo de tolerancia definido por el restaurante.

Al registrar el no-show:

* La reserva cambiará a estado `NO_SHOW`.
* La mesa dejará de estar bloqueada por esa reserva.
* La fecha y hora del registro deberán quedar almacenadas.
* La reserva deberá conservarse en el historial.

## Flujo

Consultar Reserva
↓
Validar Estado
↓
Validar Tiempo de Tolerancia
↓
Marcar como `NO_SHOW`
↓
Liberar Disponibilidad de Mesa
↓
Registrar Fecha y Hora
↓
Mostrar Confirmación

## Reglas de Negocio

**RN-076**
Solo podrán marcarse como `NO_SHOW` reservas existentes.

**RN-077**
Solo podrán marcarse como `NO_SHOW` reservas con estado `CONFIRMED`.

**RN-078**
La reserva solo podrá marcarse como `NO_SHOW` una vez superado el tiempo de tolerancia establecido.

**RN-079**
Una reserva `NO_SHOW` dejará de bloquear la disponibilidad de la mesa.

**RN-080**
La reserva deberá conservarse para efectos históricos.

**RN-081**
La fecha y hora del no-show deberán quedar registradas.

## Endpoint

```http
PATCH /api/v1/reservations/{id}/no-show
```

## Validaciones

* Reserva existente.
* Estado `CONFIRMED`.
* Tiempo de tolerancia cumplido.
* Identificador válido.

## Criterios de Aceptación

* Se puede marcar una reserva confirmada como `NO_SHOW`.
* La reserva cambia correctamente de estado.
* La mesa vuelve a quedar disponible para nuevas reservas.
* No se puede marcar como `NO_SHOW` una reserva con estado inválido.
* Se valida el tiempo de tolerancia.
* La fecha y hora quedan almacenadas.
* La reserva permanece disponible para consulta histórica.
