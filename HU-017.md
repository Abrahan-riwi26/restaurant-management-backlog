## Historia de Usuario

**Como** administrador del restaurante

**Quiero** controlar el acceso mediante roles y permisos

**Para** garantizar que cada usuario solo pueda ejecutar las funciones correspondientes a su responsabilidad.

## Objetivo

Implementar autorización basada en roles para proteger las operaciones del sistema.

## Descripción Funcional

Inicialmente se manejarán los siguientes roles:

* `ADMIN`
* `WAITER`
* `KITCHEN`
* `CUSTOMER`

Ejemplos:

* Administrador: gestión completa.
* Mesero: mesas y pedidos.
* Cocina: preparación de pedidos.
* Cliente: reservas y perfil.

## Flujo

Usuario Autenticado
↓
Validar JWT
↓
Consultar Rol
↓
Validar Permisos
↓
Autorizar o Rechazar Operación

## Reglas de Negocio

**RN-099**
Todo usuario protegido deberá poseer un rol.

**RN-100**
Los recursos protegidos requerirán autenticación.

**RN-101**
Solo los roles autorizados podrán ejecutar operaciones restringidas.

**RN-102**
Un usuario sin permisos deberá recibir una respuesta de acceso denegado.

## Endpoints

```http
GET /api/v1/roles
PATCH /api/v1/employees/{id}/role
```

## Validaciones

* Usuario autenticado.
* Rol existente.
* Permisos suficientes.

## Criterios de Aceptación

* Los endpoints protegidos requieren autenticación.
* Los permisos se validan correctamente.
* Un usuario no autorizado no puede acceder.
* Un administrador puede asignar roles a empleados.
* Los roles se aplican correctamente a las operaciones protegidas.
