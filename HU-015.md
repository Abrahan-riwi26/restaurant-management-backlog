**Dependencias**

## Historia de Usuario

**Como** usuario registrado

**Quiero** iniciar sesión utilizando mi correo electrónico y contraseña

**Para** acceder de forma segura a las funcionalidades protegidas de la plataforma.

## Objetivo

Implementar un mecanismo de autenticación seguro que permita validar las credenciales del usuario y generar un token de acceso para identificarlo en futuras solicitudes.

## Descripción Funcional

El usuario deberá ingresar:

* Correo electrónico.
* Contraseña.

El sistema deberá:

* Buscar el usuario mediante su correo.
* Validar la contraseña.
* Verificar que la cuenta se encuentre activa.
* Generar un Access Token mediante JWT.
* Retornar información básica del usuario autenticado.

El token deberá utilizarse posteriormente para acceder a endpoints protegidos.

## Flujo

Ingresar Credenciales
↓
Buscar Usuario
↓
Validar Contraseña
↓
Validar Estado de Cuenta
↓
Generar JWT
↓
Retornar Sesión

## Reglas de Negocio

**RN-088**
Solo podrán autenticarse usuarios registrados.

**RN-089**
La contraseña ingresada deberá validarse contra la contraseña almacenada de forma segura.

**RN-090**
Solo podrán iniciar sesión usuarios con estado `ACTIVE`.

**RN-091**
Las credenciales incorrectas no deberán indicar específicamente si falló el correo o la contraseña.

**RN-092**
El Access Token deberá tener un tiempo de expiración configurable.

**RN-093**
La contraseña nunca deberá incluirse en la respuesta de autenticación.

**RN-094**
Los endpoints protegidos deberán requerir un JWT válido.

## Endpoint

```http
POST /api/v1/auth/login
```

Ejemplo:

```json
{
  "email": "carlos@example.com",
  "password": "Password123"
}
```

Respuesta esperada:

```json
{
  "accessToken": "jwt-token",
  "user": {
    "id": 1,
    "firstName": "Carlos",
    "lastName": "Pérez",
    "email": "carlos@example.com"
  }
}
```

## Validaciones

* Correo obligatorio.
* Formato de correo válido.
* Contraseña obligatoria.
* Usuario existente y activo.
* Credenciales válidas.

## Criterios de Aceptación

* Un usuario registrado puede iniciar sesión correctamente.
* Se genera un JWT cuando las credenciales son válidas.
* Las credenciales incorrectas son rechazadas.
* Los usuarios inactivos no pueden iniciar sesión.
* La contraseña nunca aparece en la respuesta.
* Un JWT válido permite acceder posteriormente a recursos protegidos.
* Un JWT inválido o expirado es rechazado.
