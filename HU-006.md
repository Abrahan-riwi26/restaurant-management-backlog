# HU-006 — Consulta de Disponibilidad de Mesas

**Épica**
Gestión de Reservas

**Sprint**
Sprint 2

**Prioridad**
Crítica

**Story Points**
13

## Historia de Usuario

**Como** cliente del restaurante

**Quiero** consultar la disponibilidad de mesas para una fecha, hora y cantidad de personas

**Para** saber si puedo realizar una reserva.

## Objetivo

Permitir que el sistema determine qué mesas pueden ser utilizadas para una reserva considerando la capacidad, el estado de la mesa y las reservas existentes.

## Descripción Funcional

El cliente deberá indicar:

* Fecha.
* Hora.
* Cantidad de personas.

El sistema deberá consultar las mesas que:

* Se encuentren operativas.
* Tengan capacidad suficiente.
* No tengan una reserva que genere conflicto en el horario solicitado.

La respuesta deberá indicar si existe disponibilidad y mostrar las mesas candidatas cuando corresponda.

## Flujo

Ingresar Fecha y Hora
↓
Ingresar Número de Personas
↓
Consultar Mesas Operativas
↓
Validar Capacidad
↓
Consultar Reservas Existentes
↓
Descartar Conflictos
↓
Mostrar Disponibilidad

## Reglas de Negocio

**RN-036**
La cantidad de personas deberá ser mayor que cero.

**RN-037**
No se permitirá consultar disponibilidad para fechas u horas pasadas.

**RN-038**
Solo podrán considerarse mesas con estado `AVAILABLE`.

**RN-039**
La capacidad de la mesa deberá ser igual o superior a la cantidad de personas solicitada.

**RN-040**
Una mesa no podrá considerarse disponible si existe una reserva que genere conflicto con el horario solicitado.

**RN-041**
Las mesas `OUT_OF_SERVICE` no podrán utilizarse para reservas.

## Endpoints

```http
GET /api/v1/reservations/availability
```

Ejemplo de consulta:

```http
GET /api/v1/reservations/availability?date=2026-09-20&time=19:00&guests=4
```

## Validaciones

* Fecha obligatoria.
* Hora obligatoria.
* Cantidad de personas obligatoria.
* Cantidad mayor que cero.
* Fecha y hora futuras.

## Criterios de Aceptación

* El cliente puede consultar disponibilidad indicando fecha, hora y número de personas.
* Solo se consideran mesas operativas.
* Solo se muestran mesas con capacidad suficiente.
* No se muestran mesas con conflictos de reserva.
* No se permiten consultas para fechas pasadas.
* El sistema informa correctamente cuando no existe disponibilidad.
* La disponibilidad refleja las reservas registradas en PostgreSQL.
