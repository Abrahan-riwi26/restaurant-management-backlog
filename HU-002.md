# HU-002 — Administración de Mesas

**Épica**
Gestión Operativa

**Sprint**
Sprint 1

**Prioridad**
Muy Alta

**Story Points**
13

## Historia de Usuario

**Como** administrador del restaurante

**Quiero** registrar y administrar las mesas disponibles

**Para** controlar la capacidad y disponibilidad del restaurante para reservas y pedidos.

## Objetivo

Permitir la gestión de las mesas físicas del restaurante y disponer de información confiable sobre su capacidad, ubicación y estado.

## Descripción Funcional

El administrador podrá registrar, consultar y actualizar las mesas del restaurante.

Cada mesa deberá contener:

* Número.
* Capacidad.
* Zona.
* Estado.

Estados disponibles:

* `AVAILABLE`
* `OCCUPIED`
* `OUT_OF_SERVICE`

El sistema permitirá filtrar las mesas por:

* Estado.
* Zona.
* Capacidad.

## Flujo

Registrar Mesa
↓
Validar Información
↓
Validar Número Único
↓
Guardar Mesa
↓
Mostrar Mesa Registrada

## Reglas de Negocio

**RN-016**
El número de mesa deberá ser único.

**RN-017**
La capacidad deberá ser mayor que cero.

**RN-018**
Toda mesa nueva iniciará con estado `AVAILABLE`.

**RN-019**
Una mesa `OUT_OF_SERVICE` no podrá utilizarse para reservas o pedidos.

**RN-020**
Solo podrán utilizarse estados definidos por el sistema.

## Endpoints

```http
POST /api/v1/tables
GET /api/v1/tables
GET /api/v1/tables/{id}
PATCH /api/v1/tables/{id}
PATCH /api/v1/tables/{id}/status
```

## Validaciones

* Número obligatorio y positivo.
* Número de mesa único.
* Capacidad obligatoria y mayor que cero.
* Zona válida.
* Estado válido.

## Criterios de Aceptación

* Se puede registrar una mesa correctamente.
* No se permiten números duplicados.
* Se puede consultar el listado de mesas.
* Se puede consultar una mesa específica.
* Se puede actualizar una mesa.
* Se puede cambiar su estado.
* Los filtros funcionan correctamente.
* Los datos quedan almacenados en PostgreSQL.
